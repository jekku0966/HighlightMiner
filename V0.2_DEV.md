# HighlightMiner v0.2 development branch

`v0.2-dev` is the experimental architecture branch. The stable/simple v0.1.x implementation remains on `main`.

## Core storage change

v0.2 replaces generated analysis/review JSON state with one local SQLite database:

```text
HighlightMiner/
├── HighlightMiner.exe
├── settings.json
├── highlightminer.db
└── highlightminer_work/
    ├── .previews/
    └── clips/
```

`settings.json` intentionally remains human-editable. Large media files and generated video previews/clips remain normal files; structured analysis state moves into SQLite.

## Native Windows desktop shell

The Windows UI no longer opens a normal browser tab by default.

```text
HighlightMiner.exe
        │
        ├── Streamlit backend
        │   127.0.0.1:8501
        │   headless / loopback-only
        │
        └── pywebview
            EdgeChromium / WebView2
                    │
                    ▼
          native HighlightMiner window
```

The Streamlit application itself remains largely unchanged. `highlightminer/desktop.py` owns presentation concerns: waiting for the local server, choosing desktop/browser/server mode, starting the native window, and closing the window if the backend exits or the in-app shutdown button is used.

On Windows the default is `desktop`. An explicit troubleshooting fallback remains available:

```powershell
HighlightMiner.exe ui --browser
```

Automated packaging tests can set:

```text
HIGHLIGHTMINER_UI_MODE=server
```

so the backend can be smoke-tested without creating an interactive GUI window on the CI runner.

The embedded renderer is deliberately forced to pywebview's modern `edgechromium` backend. HighlightMiner does not silently fall back to legacy MSHTML.

## What the database stores

- analysis metadata and source VOD path;
- content/game category;
- candidate rank and original signal scores;
- transcript segments and their reaction scores;
- audio-energy/onset features;
- chat-burst features;
- Keep/Reject/Unreviewed state;
- user-adjusted start/end timing and clip title;
- export timestamp and exported file path.

Rejected candidates remain first-class data instead of being thrown away. That is the intended foundation for v0.2 preference learning: future reranking can train from original candidate attributes plus Keep/Reject/export decisions.

## UI changes

The Streamlit sidebar no longer requires browsing to `analysis.json`. It shows recent analyses from `highlightminer.db` and can load them directly.

A legacy importer remains available for existing v0.1 `analysis.json` folders. Imported v0.1 reviews, transcript data, audio features, and chat features are migrated when present.

The Windows package wraps this Streamlit UI in the native pywebview/WebView2 shell. Closing the native window shuts down the local Streamlit child process.

## File-count reduction

The 16 kHz WAV used for analysis is temporary and is removed after transcript/features are committed. v0.2 no longer creates new durable copies of:

- `analysis.json`
- `review.json`
- `transcript.json`
- `transcript_meta.json`
- `audio_features.json`
- `chat_features.json`

Legacy files are still understood by the importer.

## Security hardening in this branch

- local source-file validation and UNC/network-path rejection;
- chat/settings file size and extension validation;
- recursive chat JSON nesting limits;
- strict ranges for numeric settings and weights;
- standard Whisper model allow-list by default, with explicit opt-in for custom model repositories;
- loopback-only Streamlit server;
- headless Streamlit backend when hosted by the desktop shell;
- forced WebView2 renderer instead of legacy MSHTML fallback;
- native error dialog if the embedded desktop renderer fails;
- GitHub Actions pinned to immutable commit SHAs;
- release builds produce `SHA256SUMS.txt` beside the portable ZIP;
- `SECURITY.md` documents the local-app threat model and remaining limitations.

## Desktop runtime requirements

The Windows desktop shell uses `pywebview>=6.2.1,<7` and the system Microsoft Edge WebView2 Runtime.

`HighlightMiner.exe doctor` checks:

- pywebview importability;
- detectable WebView2 Runtime version;
- FFmpeg/ffprobe;
- CUDA/cuDNN/CTranslate2/faster-whisper as before.

The build process also runs a frozen `__desktop_probe__` that imports the packaged pywebview WinForms/EdgeChromium backend without opening a GUI window.

## Development version

The branch reports version `0.2.0.dev0`.

It is not intended to replace v0.1.x until the following real-machine paths have been validated:

1. packaged native desktop window launches cleanly;
2. closing the native window terminates Streamlit cleanly;
3. v0.1 analysis migration persists correctly in SQLite;
4. fresh VOD analysis writes directly to SQLite;
5. preview/review/export work from both migrated and fresh analyses;
6. Keep/Reject preference learning is implemented and validated.
