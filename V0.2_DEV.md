# HighlightMiner v0.2 development branch

`v0.2-dev` is the experimental architecture branch. The stable/simple v0.1.x implementation remains on `main`.

## Core storage model

v0.2 replaces generated analysis/review JSON state with one local SQLite database:

```text
HighlightMiner/
├── HighlightMiner.exe
├── highlightminer.db
├── settings.json        # migration/default/interchange only
└── highlightminer_work/
    ├── .previews/
    └── clips/
```

Large VODs, previews, and exported clips remain ordinary files. Structured application state — including the active desktop settings profile — lives in SQLite.

`settings.json` is no longer the normal UI configuration store. On first database settings use, HighlightMiner imports the local/package JSON once to preserve existing defaults/reaction phrases. After that, SQLite is authoritative; JSON remains available for explicit import/export and backups. See [`SETTINGS.md`](SETTINGS.md).

The database is source-aware:

```text
source VOD
├── analysis run 1
├── analysis run 2
└── analysis run N
```

A VOD source is identified with a sampled content fingerprint rather than its filename. Re-analyzing a known source creates a new run instead of replacing an old one. See [`RERUNS_AND_LEARNING.md`](RERUNS_AND_LEARNING.md) for the detailed cache and learning-data contract.

## In-app settings and presets

The native UI has a dedicated **Settings** page. Users can edit Whisper/inference settings, detection thresholds, timing, audio analysis windows, reaction phrases, and signal weights without opening JSON.

Signal weights use `0.00–1.00` sliders and show normalized effective percentages. Built-in weight-only presets are:

- **Balanced** — audio 0.34 / transcript 0.42 / chat 0.24;
- **Reaction-heavy** — 0.20 / 0.60 / 0.20;
- **Chat-heavy** — 0.20 / 0.25 / 0.55;
- **Audio-heavy** — 0.60 / 0.25 / 0.15.

Manual edits that no longer match a preset are treated as **Custom**. Presets never silently modify Whisper, clip timing, thresholds, or other options. If chat is unavailable its effective contribution becomes zero and audio/transcript are renormalized.

Save/reset/import/export are handled from the Settings page. Each analysis still stores its own immutable settings snapshot, so changing the active profile affects future analyses/reruns without rewriting history.

## Same-VOD reruns and cache reuse

When the UI detects prior runs for the selected VOD it offers **Load latest** or **Analyze again**. New runs normally reuse compatible expensive stages and always rerun candidate ranking.

Reusable stages are independently keyed:

- audio features by audio-analysis settings;
- Whisper transcript by model/inference settings;
- chat features by source + full chat-file SHA-256.

Changing only ranking settings can therefore rerank the VOD without another Whisper pass. Changing reaction phrases reuses transcript text and rescoring happens cheaply. **Force full reprocess** in the UI, or CLI `--no-reuse`, bypasses cached stages.

Existing pre-source v0.2 databases are migrated in place. Older analyses are attached to a source when their VOD is encountered again at the stored local path. New source-aware runs can follow a byte-identical VOD after a move/rename when it is selected again.

## Learning-ready persistence

The database stores source identity, per-source run number, analysis/settings/algorithm/feature-schema versions, content/game category, candidate rank and heuristic score, transcript/audio/chat features, richer per-candidate feature snapshots, review state, timing/title edits, review-event history, and complete export history.

Learning labels are deliberately defined as:

- **Keep → positive (`1`)**;
- **Reject → negative (`0`)**;
- **Unreviewed → unlabeled (`None`)**.

Unreviewed candidates are preserved but must not be silently treated as rejects. `learning_examples()` exposes a future-training dataset and `HighlightMiner.exe learning-stats` reports current review counts. The actual preference learner/reranker is **not implemented yet**.

## Native Windows desktop shell

The Windows UI does not open a normal browser tab by default.

```text
HighlightMiner.exe
        │
        ├── Streamlit backend
        │   127.0.0.1:8501
        │   headless / loopback-only
        │
        └── pywebview
            EdgeChromium / WebView2
                    │
                    ▼
          native HighlightMiner window
```

`highlightminer/desktop.py` owns presentation concerns: waiting for the local server, choosing desktop/browser/server mode, starting the native window, and closing it if the backend exits or the in-app shutdown button is used.

The troubleshooting fallback remains:

```powershell
HighlightMiner.exe ui --browser
```

CI uses `HIGHLIGHTMINER_UI_MODE=server` so the backend can be smoke-tested without creating an interactive GUI window.

## UI and migration behavior

The sidebar navigation now separates **Mine / Review** from **Settings**. Mine / Review keeps local source selection, source-aware history, v0.1 migration, candidate review, and export. The Settings page owns persistent app configuration.

The legacy v0.1 importer still accepts an old `analysis.json` and migrates available review, transcript, audio-feature, and chat-feature data into SQLite. Legacy imports participate in the source/run model when the referenced source VOD still exists locally.

The review UI displays candidate/Keep/Reject/Unreviewed counts, run number, and which upstream stages were reused. Export filenames are collision-safe: reruns cannot silently overwrite an existing same-named clip.

## File-count reduction

The 16 kHz WAV used for analysis is temporary and is removed after transcript/features are committed. New v0.2 analyses no longer require durable copies of:

- `analysis.json`
- `review.json`
- `transcript.json`
- `transcript_meta.json`
- `audio_features.json`
- `chat_features.json`

Legacy files remain importable.

## Security hardening

This branch includes local source-file validation and UNC rejection, chat/settings size and extension validation, JSON nesting limits, numeric setting validation, the standard Whisper-model allow-list, a loopback-only/headless Streamlit backend, forced WebView2 renderer, native desktop error handling, immutable GitHub Actions revisions, and release `SHA256SUMS.txt` generation.

Custom Whisper repositories remain an explicit advanced opt-in. Settings JSON import is validated before becoming the active database profile. The sampled VOD fingerprint is an identity mechanism, not an integrity/security checksum. See [`SECURITY.md`](SECURITY.md).

## Desktop runtime requirements

The Windows desktop shell uses `pywebview>=6.2.1,<7` and the system Microsoft Edge WebView2 Runtime.

`HighlightMiner.exe doctor` checks pywebview, WebView2, FFmpeg/ffprobe, CUDA/cuDNN, CTranslate2, and faster-whisper. Packaging also runs a frozen desktop-runtime import probe and a server-only Streamlit HTTP smoke test.

## Development version and validation status

The branch reports version `0.2.0.dev0`.

Before it replaces v0.1.x, real-machine validation still needs to cover:

1. packaged native desktop launch/shutdown and Settings navigation;
2. save/reset/import/export of database-backed settings;
3. v0.1 → SQLite migration with real historical review state;
4. a fresh VOD analysis written directly to SQLite using the saved app settings;
5. same-VOD detection and a cached rerun on a real long VOD;
6. forced full reprocess behavior;
7. preview/review/export from multiple runs without collisions;
8. persistence of Keep/Reject/Unreviewed and timing changes across restarts;
9. eventual preference learner/reranker behavior once that learner is implemented.
